# Idea bank

Read this file when a plan needs ideas beyond its funnel moves. An idea enters the plan only when its precondition holds in the supplied evidence. Each first test is cheap and reads one leading indicator for one stage. The owner sets the window, the baseline source, and the stop criterion.

## Reach

- **Owned media (a podcast or video channel that the owner controls).** Precondition: buyers ask recurring questions the owner can answer on tape, and one person can record and publish each period. First cheap test: one episode that answers the most frequent question in the supplied records; read its Reach indicator against the supplied baseline.
- **Awards.** Precondition: the product has a result that a named award accepts as an entry. First cheap test: read the award's current entry rules and fee on its official page, then enter only if a budget line pays the fee.
- **Developer relations (direct work with developers: talks, answers, sample code).** Precondition: the buyers are developers, and the owner can name the forum or event where they ask questions. First cheap test: answer the questions in that one forum for one period, and record the visits that link back.
- **International expansion.** Precondition: supplied records show buyers in a second market, and the owner has checked that market's current tax and consumer rules on its official page. First cheap test: one page in that market's language for the buyers who already enquired, read against the first market's supplied baseline. This skill does not size the market; the owner supplies that figure.
- **Creator cohort (several creators, added in stages).** Precondition: a supplied budget line pays the creator fees. First cheap test: the owner states the starting count of creators; without it, write `[PLACEHOLDER: creator count]`. Evaluate each creator one at a time with `hl-creator-deal`. Add a later creator only to fill an audience or format gap that the first results show. Read each creator's Reach indicator against the supplied baseline; the stop criterion is a signal the owner can read, as in workflow step 7.

## First value

- **Public demos (a live or recorded product run in public).** Precondition: the first value of the product can be shown in one session without an account. First cheap test: one recorded run of that first-value path, published on a channel the owner already uses; read its First value indicator against the supplied baseline.

## Retain

- **Year-end summaries (a recap of each user's own results).** Precondition: the product records each user's results, and the owner has checked that the recap uses only those results under the applicable privacy rules. First cheap test: send the recap to one active segment, and compare its Retain indicator with a held-back segment designed with `hl-ab-test-plan`.
- **Certification (a course or credential the owner issues to users).** Precondition: the owner can assess a skill that users need, and can name who does the assessment. First cheap test: one assessed module offered to existing active users; read its Retain indicator against the supplied baseline.

## Refer

- **Community challenges (a public task run for the user community).** Precondition: the community already posts its work in one public place. First cheap test: one challenge in that place with a written entry rule; read its Refer indicator for the period.
- **Open source (a public component or tool the owner releases).** Precondition: the component contains no customer data or secrets, and someone can answer its issues for the period. First cheap test: release one small component, and read the sign-ups that come from its repository.

## Revenue

- **Switching offers (an offer for buyers who leave a named rival).** Precondition: supplied win/loss notes name that rival, the rival's current terms are checked on its official page with a date, and the offer price is above the supplied cost to serve. First cheap test: one offer to the buyers who named that rival, paid from a budget line, read against the Revenue indicator.
