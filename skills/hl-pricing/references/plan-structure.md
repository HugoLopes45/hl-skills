# Plan Structure and Access Model

Read this when setting the number of plans, the levers that separate them, the access model (freemium, trial, paid entry), or an enterprise plan.

## Plan count

Match the count to the distinct buyer groups.

- Use two plans for a clean split between two groups.
- Use three plans when three groups are distinct. Three is a heuristic default, not a rule.
- Use four or more plans only for a wide range of buyer sizes. Each extra plan adds a decision for the buyer.

## Levers

Separate plans with one or more levers:

- **Feature gating.** A capability appears only in higher plans. Use it when the difference in value is clear to the buyer.
- **Usage limits.** The same features with higher limits on users, storage, or calls. Use it when value scales with usage.
- **Support level.** A faster or more personal channel. Use it when buyers need help to get started.
- **Access features.** Integration access, single sign-on, or custom branding. Use it for organization buyers.

## Access model

Choose the access model from the market. Market evidence includes price level, buyer sophistication, sales complexity, time to value, and competitor norms. Name the evidence behind the choice.

- **Freemium.** A free plan with no end date. Use it when the free plan spreads the product through sharing or network effects, or when serving a free user costs little. Structure the free plan to deliver value, and state its limits before signup. Do not give enough free use that the paid need disappears. Set a free limit that normal use reaches. Test a hard paywall (no core use without a trial or purchase) against it on the same eligible traffic.
- **Free trial.** Full or near-full access for a fixed period. Use it when value needs setup or time to appear, or when the price is high.
- **Reverse trial.** Full access for a fixed period, then a free plan. Use it when buyers must see the premium value before they accept the limits. Test it against a plain free trial on the same eligible traffic.
- **Freemium with a trial.** A free plan with limited features, plus a trial of the paid features. Use it when the free plan spreads the product and the paid features need time to show value.
- **Paid entry.** A low-cost paid start for a short period. Use it when buyers must show commitment before full access.
- **Money-back.** Full price with a refund window. Use it when value arrives inside the refund window.
- **Consultation.** A person runs a session before access. Use it for complex or high-touch products where a person must bring the buyer to value.

Treat trial length as a test. Compare lengths on the same eligible traffic, and do not copy a length from another product.

Treat the card requirement at signup as a test. A higher trial-to-paid rate among card givers does not show more paying customers. Compare visitor-to-paid over the same horizon and eligible traffic. Include refunds, early cancellations, and support cost.

## Enterprise plan

Add a custom-priced plan when buyers ask for a contract, a security review, procurement steps, or implementation help.

As a heuristic, expect these table stakes from organization buyers: single sign-on, audit logs, admin controls, an uptime commitment, and security certifications. State only the commitments you measure and can deliver.

Offer dedicated support, custom onboarding, and training as added value.

Name the deal terms that need approval and the role that approves each: a discount off list price, non-standard payment terms, a multi-year term, or custom legal terms. The owner sets each threshold.

Price the custom plan with the models in [pricing-models.md](pricing-models.md). A volume discount is a discount: apply the rule in [price-changes.md](price-changes.md).
