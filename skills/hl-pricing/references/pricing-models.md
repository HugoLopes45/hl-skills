# Pricing Models

Read this when choosing how to charge on the value metric.

The value metric sets the unit. The price model sets how that unit is charged. Pick the primary model first, then add a second model only when the first one clearly misprices a buyer group.

## Models

1. **Flat.** One price for one product. Use it first when it fits. As a heuristic, it is the easiest to sell and understand. It leaves money on the table with the largest buyers.
2. **Usage.** Charge for metered consumption. Use it when value tracks volume and buyers can predict their volume. Add spend caps or alerts, because an unpredictable bill can stop a purchase.
3. **Tiered.** Several plans at set prices. Use it when buyer groups differ in needs and budget. Plan design: see [plan-structure.md](plan-structure.md).
4. **Per seat.** Charge per user. Use it only when value rises with headcount. If value does not rise with headcount, seats can discourage adoption, for example when teams share logins to avoid paying. Check for shared logins in the usage data.
5. **Feature.** Gate capabilities by plan. Gate the features that separate casual users from serious users. Do not gate the feature that delivers the core value.
6. **Credit.** Buyers prepay a balance and spend it on actions. Use it when usage is lumpy or each action has a different cost.
7. **Outcome.** Charge per result the buyer gets. Use it only when the result is measurable and clearly caused by the product.
8. **Hybrid.** Combine a base fee with a usage or outcome part. Use it when one model misprices a real buyer group.
9. **Lifetime access.** One payment for access that does not end. Use it only when the total cost to serve is known or capped over a stated period. The price must cover that cost; state the period as an assumption.

## Combining models

- Seats within each plan, for B2B products with several buyer groups.
- A base fee with usage above an allowance, for predictable revenue with upside.
- Seats plus credits, when heavy actions need their own purchase.
- Feature plans plus outcome charges on top, when the outcome is measurable.

Name the buyer group that a second model fixes. Without a named buyer group, keep one model.

## Value before price

If you cannot state the value the buyer gets, in the buyer's terms, fix the offer and positioning before you change the price.
