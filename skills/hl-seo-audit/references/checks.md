# Audit checks

Each item lists what to read, the rule for a finding, and the evidence to quote. Use the tools you have. Without a fetch tool, use the HTML and exports the user supplied, and mark header checks "not read".

## Indexing

- **Status and final URL**: read the response status and the URL after redirects. Pass: 200 on the intended URL. Finding: 4xx or 5xx, a redirect chain, or a redirect to an unrelated page. Finding, Low: a meta refresh redirect; fix: a server-side 301.
- **Robots meta**: read `<meta name="robots">` and any `googlebot` meta. Finding: `noindex` or `none` on a page intended for search. If intent is unknown, report the exclusion and confirm intent before recommending removal.
- **X-Robots-Tag header**: read it when you have response headers. Finding: `noindex` on a page intended for search; preserve intentional exclusions.
- **robots.txt**: read the status code first. 2xx: the rules apply. A 4xx other than 429: Google treats it as no robots.txt, so no restrictions. A 429: check its treatment in the current Google robots.txt specification; without web access, write that this was not checked. A redirect chain longer than five hops is treated as a 404. A 5xx or a timeout: Google stops crawling the site for the first 12 hours, then uses the last good copy for 30 days; with no cached copy it assumes no restrictions. Find the rules for the page path: the most specific user-agent group naming Googlebot applies, a named group ignores `*`, the longest matching path wins, and a tie goes to allow. robots.txt over 500 KiB is ignored past that size. Source: Google robots.txt specification, checked 2026-11-17, https://developers.google.com/crawling/docs/robots-txt/robots-txt-spec. When the page should rank in another search engine, check that engine's crawler rules against its current documentation; without web access, write that this check was not run. Finding: a disallow on a page that should rank, or on CSS or JavaScript files that Google needs to render the page. A robots.txt disallow stops the crawler from reading a noindex tag on that page, so the page can still appear without its content. Never recommend noindex and disallow on the same URL.
- **Canonical**: read `<link rel="canonical">`. Finding: two different canonicals on one page (two tags, or a tag and a Link header); a canonical that points to a redirect, an error page, or a noindex page; or a canonical that conflicts with the intended canonical. Another URL can be correct for a duplicate; confirm the page's live URL and intended canonical before changing it. Before you say how strictly search engines follow a canonical, check the current Google documentation; without web access, write that this was not checked.
- **Pagination**: read the canonical on each page of a paginated series. Finding: page 2 or later points to page 1 although the pages are not duplicates. Before recommending a change, check the search engine's current pagination guidance; without web access, write that this was not checked.
- **Sitemap**: when supplied, check that the URL is listed. Finding: the sitemap lists a noindex or noncanonical URL, a URL that redirects or errors, or a URL that robots.txt blocks. Absence alone is not an indexing blocker; assess discovery through internal links too. When none is supplied, read the `Sitemap:` lines in robots.txt, then `/sitemap.xml` and `/sitemap_index.xml` when you can fetch them. Finding, Low: a sitemap that robots.txt does not name.
- **Soft 404**: with the user's approval, request one made-up URL on the same host, if you can fetch. Finding: it returns 200, directly or after a redirect. Fix: return 404 for unknown URLs and keep the friendly page.
- **Staging and proxy hosts**: read the robots meta, X-Robots-Tag, and canonical on the production response, and on the origin or staging host when it is supplied. Finding: `noindex` on a page intended for search in the production response, or a canonical that names the origin or staging host instead of the main domain. A `noindex` set only on the origin can pass through a proxy to production.
- **Crawl budget**: read the parameter, faceted-navigation, and session-ID URLs in the link set or export. Finding: such variants with no canonical, redirect, or robots.txt rule. Apply this only when the export contains such URLs.

## Technical

- **HTTPS**: read the URL scheme. Finding: `http://`, or HTTPS pages that load `http://` resources. A browser warning or failed TLS handshake on any host variant, www and the bare domain included, is High when observed by fetch on the canonical host; otherwise Medium. A missing `Strict-Transport-Security` header on an HTTPS site is Low; read it only when you have response headers.
- **Primary content in HTML**: check that the main text and links appear in the static HTML. If missing from static HTML, mark rendered content unconfirmed. Call it rendered-only only after observing it in the rendered DOM.
- **Viewport**: read `<meta name="viewport">`. Finding: missing on a page meant for phones.
- **Mobile parity**: when a phone-width capture and a desktop capture are both supplied, compare their main text and links. Finding: main content or links present on desktop and missing on phone. Note horizontal scroll and crowded tap targets in the phone-width capture as observations.
- **Field speed**: when Search Console or Chrome UX Report data is supplied, compare LCP (2.5 s or less), INP (200 ms or less), and CLS (0.1 or less) with "good". Lab results are labeled lab data.
- **Server response**: when time to first byte readings are supplied, flag a server whose time to first byte (the wait before the first byte of the response) is slower than 1.8 seconds on at least one fifth (20%) of the sampled pages. web.dev rates a time to first byte above 1.8 seconds as poor and notes it is not a Core Web Vitals metric (https://web.dev/articles/ttfb, checked 2026-11-17); the one fifth is a heuristic default. Say that the readings came from one location at one time.
- **Duplicate URLs**: parameter or trailing-slash variants that serve the same content. With the user's approval, if you can fetch them, compare http, https, www, and the bare domain; each variant that answers on its own is a duplicate; point it to the chosen version with a 301 redirect or a canonical. Finding: duplicates with no canonical or redirect.
- **URL structure**: read the path of each indexable URL. Finding, Low: uppercase letters, underscores, IDs or query strings in place of words, or pages of one type under different parent paths. Fix for an unpublished URL: a lowercase, hyphenated slug, with each page type under one parent path. Do not recommend changing a live URL for this alone; when a live URL changes for another reason, redirect the old one with a 301.

## On-page

- **Title**: read `<title>`. Finding: missing, empty, duplicated across pages, only the brand name, generic (such as "Home"), or stuffed with keywords or repeated boilerplate. Judge truncation in a search preview; a character count is a rough guide only. Before you say a search engine may rewrite a title that is too long, stuffed, generic, or out of line with the H1, check its current title guidance; without web access, write that this check was not run. A title that promises a different page type or answer than the main text is a finding when the target intent is established. Put the target query first, then the reason to click, then the brand when the title shows one.
- **Title shape**: match the title to the page type. A product or service names the category and audience; a comparison names both options and the deciding difference; a how-to names the task. Finding, only when the target intent is established: a title that names another kind of page or task.
- **Title promise**: use "free", a year, or a number in a title only when the page delivers it. Finding: one of these in a title the page does not deliver. Do not change a URL slug to add one.
- **Bulk titles**: for a crawl export, list one row per page with a title finding: URL, current title, proposed title, reason. Propose a title only when the target query is supplied; give 2-3 proposed titles (heuristic default) only for revenue pages the user names.
- **Meta description**: read `<meta name="description">`. Finding: missing or duplicated. Search engines may write their own snippet, so rate this Low unless the copy itself is weak.
- **H1**: read the visible `<h1>` elements and the document outline. Multiple H1s are valid; different section labels do not prove competing topics. Without established target intent or a demonstrated outline problem, report the headings as observations, not defects. Do not recommend keeping one H1 or converting another to H2 based on count or different labels alone. A finding needs evidence that the outline misrepresents the content or hides its main topic.
- **Heading order**: read the H2 and H3 sequence. Finding: heading levels chosen for size, not structure.
- **Internal links**: read the anchor text of links into and out of the page. Finding: anchors such as "click here", or no links in or out. Also check each internal link target from the menu, footer, homepage, and key pages, when you can fetch them. Finding: a target that returns 404, 410, or 5xx; a 401, 403, or 429 response is not checked, never broken. Fix it once at the menu when the link is sitewide.
- **Images**: read `alt` on informative images. Finding: missing alt text on an image that carries meaning. Also read `width` and `height` on informative images; a missing value is Low, because the layout shifts while the image loads. Finding, Low: an image larger than its display size; fix: resize it, and serve a modern format with a fallback. Images below the fold without lazy loading are Low.
- **Social preview tags**: read `og:title`, `og:image`, and `twitter:image` in the `<head>` of key pages. Finding, Low: `og:title` or `og:image` missing. Before you flag a missing `twitter:image`, check that platform's current guidance; without web access, write that this check was not run. Check the image size against each platform's current sharing guidance; without web access, write that this check was not run.
- **Language attribute**: read `lang` on the `<html>` element. Finding, Low: missing, or not the language of the page.

## Content

- **Target match**: read the first screen. It should state what the page is, who it is for, and the answer to its target query. Finding: the page answers a different query.
- **Supported facts**: check each specific claim for a source or a first-party fact the user supplied. Finding: unsourced statistics, rankings, or "best" claims.
- **Expertise signals**: check for an author, dates, and sources on topics that depend on expertise, such as health, money, or law. On other articles, rate a missing date or author no higher than Low. Search engines describe these signals in their quality guidance; none is a single score.
- **Depth**: judge depth against the query's intent, not word count. Without a target query or established intent, leave adequacy unconfirmed; short copy and multiple headings alone do not establish a content defect. Before calling a page thin, read its full main text and check for a clear offer, price range, or booking form; a short page with one of these may do its job.
- **Duplicate text**: when two or more pages are supplied, compare their main text. Finding: identical main text, or pages that differ only by a place or product name, such as town pages with only the town swapped, unless one page canonicalizes, redirects to, or is noindexed in favor of the other. Fix: when the supplied search export shows clicks for a copied page, rebuild it with facts specific to its place or product; when it shows none, 301-redirect it to the nearest kept page. Without an export, write "not measured" and do not choose between them.
- **Cannibalization**: with a search-performance export, find queries where two supplied pages both rank. Finding: two of your pages split one query when both serve one intent. Fix: after confirming the intent, choose one owner page, merge the other's unique content into it, and 301-redirect the retired URL to the owner.

## AI-answer readiness (GEO)

- **Direct answer**: assess this only when established query intent calls for an answer. With no target intent, mark answer fit unconfirmed: do not rate absent question-led copy as a defect, even Low, or infer snippet or AI effects. Question headings and one- or two-sentence answers are optional formats, not universal search requirements. A finding needs a demonstrated mismatch with the known intent.
- **Checkable facts**: each factual sentence has a number with its unit, a date, or a source. Finding: numbers with no unit or source.
- **Structure**: recommend lists, tables or definitions only where they improve a demonstrated readability problem. Prose alone is not a search or AI-answer defect.
- **Limits**: one page does not show whether AI systems retrieve or cite it. State that limit when you recommend GEO work.

## Structured data

- **JSON-LD in static HTML**: read `<script type="application/ld+json">`. Found: list each type and check that it matches visible content. Not found: write "not in static HTML"; never write "absent".
- **Rendered check**: needed before you claim markup is absent. Ask the user for a rendered-DOM read, or for the output of a rich-results test.
- **Mismatch**: markup describes content the page does not show. Finding: High, because it misleads search engines and readers.

## Links

- **Paid or exchanged links**: read the supplied outbound links and any note on sponsorship, paid placement, or link exchange. Check each against the search engine's current link spam policy, including the rel value that policy requires for it. Finding: a paid or exchanged link without the required rel value. Fix: add the required rel value, or remove the link. Without web access, write that the policy check was not run.
