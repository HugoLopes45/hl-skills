# Site types and usual sections

Read this file from the Site structure mode in `SKILL.md`. Classify the site from the supplied page list or offer list. Use the signals below as evidence; a type with weak signals is a guess, and say so.

## Types

- **Software product.** Signals: feature pages, pricing, sign-up or login, a link to documentation or a changelog. Usual sections: Product or features, Pricing, Use cases, Documentation, Changelog, Support, Company, Legal.
- **Content site.** Signals: dated articles by an author, topic categories, a newsletter sign-up. Usual sections: Topic hubs, Guides and articles, Author or About, Contact, Archive.
- **Shop.** Signals: product pages with a price and an add-to-cart control, product categories. Usual sections: Categories, Products, Brands, Shipping and returns, Help.
- **Documentation.** Signals: reference or API pages, versioned guides, release notes. Usual sections: Getting started, Guides, Reference, Tutorials, Release notes.
- **Mixed.** Signals: two of the types above, each with clear signals. Usual sections: the usual sections of both types; name both types in the classification.
- **Small business.** Signals: services with a call, quote, or booking request; no product catalogue. Usual sections: Services, Prices or quotes, Service areas, About, Reviews, Contact or booking, FAQ.

## Navigation

For a planned site, give each page in the draft its URL and navigation location, from the owner's page list; the nesting shows its parent. Mark each URL `proposed`.

In a documentation section, the sidebar marks the current page. A site too large to browse by navigation has a reachable search.

## Naming

Use the owner's own names for a section when the supplied material already uses one. The usual section name is a fallback.
