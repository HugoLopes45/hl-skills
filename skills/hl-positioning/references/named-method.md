# Named method

Use this file in workflow step 5 when an attribute could be a method. A method is the how behind a promise: a step the product does today that the buyer can see.

## Gate

- Name only a step that the supplied facts or a source read in this session shows the product does today.
- Never build a method from how the product might work.
- A planned step is a claim that lacks proof. List it with the line it would unlock and what it takes to make it real.

## Kinds

1. **Existing and unnamed.** The product already does the step, and nobody calls it a method. Name the step.
2. **New.** An original process, equipment or software that no rival has. It counts only once it is live.

## Naming

Name the method after a number, a step or the result. Invented examples: "the three-visit check", "the same-day parts count". Reject "our proven process", "a holistic approach" and "the [brand] difference".

## Explaining

Write two sentences, one with a "because". Invented example: "We photograph each delivery note before we invoice, because a missed line is what a customer disputes first. Every invoice shows that photo, so the buyer can check the amount."

## Tests

- **Believability.** Does the method make the promise more believable? If not, it is decoration.
- **Differentiation.** Could a rival say the same sentence word for word? If yes, make it more specific.
- **Visibility.** Can the buyer see the step happen, as a photo, a report or a check-in?
- **Explanation.** Two sentences, no jargon.
- **Buyer reaction.** When a buyer hears it, does the buyer say "I haven't tried that" or "I've heard that"? Only the first passes. If no buyer has heard it, mark the test `unknown`.

## Reject

- A credential presented as a method, such as "licensed", "certified" or "years in business".
- A name with no step behind it.
- A difference that does not change the result.
- A method the team skips on some jobs. One skipped step turns the method into a complaint.
