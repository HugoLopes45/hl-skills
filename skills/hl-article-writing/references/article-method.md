# Editorial article method

Use this method for an explanatory article, not a landing-page sales structure, email campaign or search brief.

## Structure

- Title: state the article's subject or useful answer without unsupported outcomes.
- Summary: represent the body honestly; do not move an unsupported figure here after removing it from the body.
- Opening: give the answer in the first two or three sentences. Cut throat-clearing and announcements such as "this article will".
- Outline: one point per planned section.
- Body: explain each point with actual paragraphs and supported details. An outline is not a finished article. Start each major section with a sentence that answers its heading on its own, with no dangling pronoun. Write each subhead to stand alone as a point, so a reader or a social cut understands it without the body.
- Claims: say each claim once at full strength. A later section adds a point instead of restating an earlier one.
- Names: use one name per entity throughout, and define it at first mention.
- Credentials: place an author credential inside the point it supports, never in the opening.
- Limits: when the sources state limits, a full explanatory article has a section on where the advice fails and which figures are vendor data. A partial request includes it only when the requested part makes the claim it limits.
- Comparisons: give a verdict only when each option has two facts across two dimensions (a heuristic default). Label each fact's source, and state who each option suits ("choose X if ...").
- Filler: cut a paragraph that would fit any other business; replace it with the subject's specific substance.
- Case study: when the piece is one, run challenge, solution, results and key learnings in that order; tie each result to a supplied figure with its date and source.
- Links: place at most one link per paragraph (a heuristic default), and put the closing action on its own short line.
- Copyable steps: put only text the reader pastes in a code block, with variables in square brackets. List each such block in the Sources and assumptions note as run in this session or not run.
- Ending: answer the reader's question, summarize the useful action, and point to a verified destination you own when one is supplied: the publisher's site, email list or community. A rented platform is never the only endpoint.

Produce only requested sections. When a title, summary or body is requested alone, do not require an entire package.

## Source and permission check

- Each statistic carries source name, date, population and relevant geographic scope. Missing provenance is a placeholder, not a new research finding. Follow a figure to its original study; otherwise keep the placeholder.
- Rank sources: official statistics for the article's market, then large independent studies, then industry associations, then vendor data labelled "(vendor data)", then first-hand counts the author confirms. Use a lower rung only when the higher ones lack the figure among sources supplied or read in this session.
- Each quote needs exact supplied words, speaker and permission. Links must be supplied or read in this session.
- Quote a figure as its source words it: keep "may", "up to" and similar qualifiers.
- Check evidence for health effects, comparisons, rankings and time-bound results. A country change does not justify changing a supplied price, currency, fact or study population.
- Show an old figure with its year; never present it as current. Label money or result arithmetic as arithmetic, not a promise, and label any hypothetical example as hypothetical.
- Give each curated list or comparison a visible update date, and update it when its subject changes.
- Where the user supplies first-party data, use one figure from it in each major section it supports, with its unit, date and sample. Write a data report only from data the user supplies, with the data's date and scope.
- Preserve original arguments when reviewing. Do not replace a specific limitation with a broad claim.

## Publishing context

Use the named channel and account context only where they affect delivery. Check applicable title and summary fields, media limits, original-content declarations, reprint rights, advertising or promotion placement, comments, sponsorship labels and destination capabilities against current official sources.

Record each source and date. If a page cannot be read, including a script-rendered rule center, mark only the affected rule unverified and request an official excerpt when consequential. Do not create a country-specific legal section or demand platform limits merely because a market or channel was named.

Translate the artifact and its labels as requested. Translation does not establish local legal compliance, platform compatibility, a new market's demand or the validity of a transferred statistic. A translated article needs review by a native speaker before publication.

## Quality check

Run these checks before handover.

- AI-tell check (draft mode only): rewrite banned words such as "delve", "leverage" and "game-changer"; a triple list written by reflex; a stack of hedges; balance that takes no position; a closing summary that repeats the introduction; uniform certainty with no stated doubt. Replace each hit with a specific claim, or cut it.
- Rhythm pass (draft mode only): rewrite any sentence that reads as a slogan; vary sentence length.
- Mechanical check, as a checklist: no `TODO` or `TK` marker remains; each `[PLACEHOLDER: proof needed]` is listed in the Sources and assumptions note; each paragraph with a number has its source beside it; the section headings, read in order, carry the argument.
